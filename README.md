## Обзор

Проект реализует доменную модель различных банковских продуктов, общая функциональность которых определяется с помощью абстракций и интерфейсов.

Поддерживаемые продукты:

* **Дебетовая карта (Debit Card)** - поддерживает пополнение и снятие средств в пределах доступного баланса.
* **Кредитная карта (Credit Card)** - поддерживает пополнение и снятие средств в пределах установленного кредитного лимита, а также расчет задолженности с учетом процентной ставки.
* **Вклад (Deposit)** - поддерживает пополнение и закрытие. После закрытия вклад нельзя пополнить повторно.

## Возможности

* Общие абстракции для банковских продуктов и их свойств.
* Интерфейсы, определяющие доступные операции с банковскими продуктами.
* Валидация денежных сумм и точности дробной части в соответствии с валютой.
* Защита от некорректных операций и недостатка средств.
* Контроль кредитного лимита и расчет задолженности.
* Управление жизненным циклом вклада, включая закрытие и запрет операций с закрытым вкладом.
* Модульные тесты, охватывающие стандартные сценарии, граничные условия и некорректные входные данные.
* Генерация отчетов о результатах тестирования с помощью Allure Report.

## Используемые технологии

* **Java 21** - язык программирования.
* **Maven** - сборка проекта и управление зависимостями.
* **JUnit 5** - модульное тестирование.
* **AssertJ** - библиотека для написания выразительных проверок в тестах.
* **Allure Report** - формирование наглядных отчетов о результатах тестирования.

### Основные абстракции

* `BankProduct` - общий контракт банковского продукта.
* `Fundable` - контракт, определяющий возможность пополнения средств.
* `Withdrawable` - контракт, определяющий возможность снятия средств.
* `Closable` - контракт, определяющий возможность закрытия продукта.
* `DebtHolder` - контракт для получения информации о задолженности.
* `AbstractBankProduct` - базовый класс, содержащий общие свойства банковских продуктов, валидацию и операции с балансом.
* `MoneyValidator` - проверяет точность денежных значений с учетом допустимого количества знаков после запятой для соответствующей валюты.

### Реализации банковских продуктов

* `Card` - базовый класс карточных продуктов, реализующий общую логику пополнения и снятия средств.
* `DebitCard` - контролирует, чтобы снятие средств не превышало доступный баланс.
* `CreditCard` - контролирует соблюдение кредитного лимита и рассчитывает задолженность с учетом установленной процентной ставки.
* `Deposit` - управляет пополнением вклада и его состоянием, включая закрытие.

## Архитектурные решения и паттерны проектирования

### Шаблонный метод

Шаблонный метод используется для организации общей последовательности выполнения операции при возможности изменять отдельный этап ее выполнения в подклассах.

### Rich Domain Model

В проекте используется подход Rich Domain Model, где доменные объекты не ограничиваются хранением данных, а инкапсулируют бизнес-логику и правила работы с ними.

### Наследование и повторное использование кода

Общие свойства и операции вынесены в базовые классы `AbstractBankProduct` и `Card`.

Это позволяет повторно использовать общую логику и реализовывать в продуктах только отличающиеся бизнес-правила.

## Тестирование

Для модульного тестирования используются JUnit 5 и AssertJ.

Набор тестов охватывает следующие сценарии:

* Инициализация банковских продуктов и валидация параметров конструкторов.
* Успешное пополнение и снятие средств.
* Некорректные денежные суммы и неподдерживаемая точность валюты.
* Недостаток средств и превышение кредитного лимита.
* Расчет задолженности по кредитной карте и правила округления.
* Закрытие вклада и попытки выполнения операций с закрытым вкладом.
* Сохранение состояния продукта после отклонения операции.

Для запуска всех тестов выполните команду:

```bash
mvn clean test
```

## Отчеты о тестировании и покрытии кода

### Allure Report

Запустить тесты:

```bash
mvn clean test
```

Сформировать отчет и открыть его в браузере:

```bash
mvn allure:serve
```

Команда `allure:serve` генерирует отчет на основе результатов тестирования и запускает локальный веб-сервер для его просмотра.

По умолчанию Allure Maven Plugin ищет результаты тестирования в каталоге `banking-products/allure-results`
